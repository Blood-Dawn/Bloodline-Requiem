## 💡 KEY INSIGHTS & DESIGN DECISIONS

### Why This Architecture?
1. **Modular**: Each system in separate file for maintainability
2. **Scalable**: Easy to add new abilities, factions, origins
3. **Documented**: Every pattern has examples in guides
4. **Lore-Integrated**: Codex accessible from gameplay
5. **Automated**: Rank-ups trigger ability selection automatically

### Design Principles Applied
- **Separation of Concerns**: Systems vs Content vs Lore
- **DRY (Don't Repeat Yourself)**: Shared progression logic
- **Convention over Configuration**: Clear naming patterns
- **Progressive Enhancement**: Core systems first, features later
- **Documentation as Code**: Guides updated with implementation

### Technical Constraints Addressed
- ChoiceScript lacks arrays → Used individual boolean flags
- No dynamic choice generation → Pre-coded all ability options
- Limited string manipulation → Used semicolon-separated lists
- Manual scene_list management → Organized by category
